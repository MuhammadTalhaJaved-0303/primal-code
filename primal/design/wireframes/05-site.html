Screen 3 · Install — the unsigned warning explained before it happenstwo columns, macOS and Windows

7macOS (Apple Silicon) PrimalCode-macos-arm64.dmg · SHA-256 ▸
  1. Open the DMG, drag Primal Code to Applications.
  2. First open shows "Primal Code" Not Opened — Apple could not verify…. Press Done.
  3. System Settings → Privacy & Security → Open Anyway next to "Primal Code was blocked", then confirm.
  4. Older macOS: right-click the app → Open. Terminal alternative: xattr -dr com.apple.quarantine "/Applications/Primal Code.app"
Why: the build is signed with a valid ad-hoc signature but no Apple Developer ID, so Gatekeeper cannot check it. The checksum lets you verify what you downloaded is what we published.
8Windows (x64) PrimalCode-Setup-Windows-x64.exe · SHA-256 ▸
  1. Run the installer.
  2. SmartScreen shows Windows protected your PC. Click More info → Run anyway.
  3. Install as usual; Primal Code opens on Primal Start.
Why: no code-signing certificate yet. Same fix as macOS — a certificate — and the same decision (D2).
9What happens on first launch — a short boot readout (agent host, providers, vibe, workspace) · Primal Start with a three-card FIRST RUN strip: Pick a vibe → Connect a model → Start · the model card finds an existing Claude Code login by itself · your first agent prompt downloads the Claude agent once (progress shown as a notification).
7Steps mirror 01 · Screen 1 word for word. The right-click path is kept for older macOS only; verifying which OS versions still honour it is an open item. SHA-256 files already exist per release (the .sha256 next to the DMG) — link them.
8SmartScreen wording matches the current FAQ ("More info → Run anyway"). The Windows build's exact dialog text was not verified from this worktree — screenshot it on the next Windows CI build.
9Sets expectations for the two waits the wireframes found: the model card's "Looking for an existing setup…" (up to 60 s) and the one-time SDK download. Saying it here is cheaper than a support issue.
