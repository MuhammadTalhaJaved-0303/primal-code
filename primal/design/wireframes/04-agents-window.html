04 — The Agents window: landing and session view

Stories 2 and 3 — the window where agent work starts and is reviewed. Also answers two placement questions: where the motif stage may live, and where model/provider state is shown.

1Shipping sessions list: grouped by workspace, "Chats" group, status words. "New Session" is the shipping action label ("New Session ({0})" with the agent name when several are configured).
2Shipping customizations tree (six categories, lazy, 20-row cap) with the draggable sash whose height persists under agentSessions.customizationsPane.height. Counts are real item counts ("{0}, {1} items").
3The only place a motif may live in this window: the landing stage behind the composer card, at the same 35 % ceiling as Primal Start (PR #23; the composer card is its own scrim plate), never behind a stream or code (the motif setting's own text: contrast of text over something that moves cannot be checked). The card is opaque. Because this window has no status bar, a small "motif: resting · pause" control belongs in this corner — decision D11.
4Shipping "Send your first prompt" options widget (newSessionPromptOptions.ts) — suggestions are data from the composer service; closing it is remembered.
5Provider strip, proposed. One line, always visible on the landing, sourced from the same detection the settings page uses (keychain login probe, saved keys, SDK presence). Words, not dots: "ready" / "key saved" / "no key" / "downloading" / "not available". "Manage providers" runs primalCode.manageProviders.
