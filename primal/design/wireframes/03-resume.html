Story 3 — "Come back tomorrow" · success = within 30 s of launch the user can name the session they were in, see what it changed, and continue it or apply it, without opening a file by hand.

1Boot overlay lines on a return visit; "workspace acme-api" is the reassurance that the right project is restoring. ≤ 1.4 s, any key dismisses.
2Shipping Rig rows: name, dimmed path, last-opened relative time (IWorkspacesService recents). The branch column is deliberately absent — the recents pipeline records none.
3Shipping Rig rows with the four status words (Running / Waiting on You / Done / Failed) and "no status" when nothing truthful is recorded. Proposal: append the worktree branch when the session has one, so "what did it change" and "where" are answered on the landing surface. Clicking a row opens the session.
4Shipping stat with its honest caption. "0" at 09:00 is correct and a little deflating; proposal: also show "yesterday: 2" from the same index (countSessionsToday with a shifted window) — decision D10.
5Update notifier, verbatim strings, ≥ 20 s after restore. It never downloads by itself; it says so in the setting description. Kept as a toast, not a banner, so it never competes with the return surface.
